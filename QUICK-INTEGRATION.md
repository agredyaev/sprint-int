# Quick → GitHub Pages handoff

1. Read `skills/sprint-intelligence/references/orchestration.md` and `skills/sprint-intelligence/references/storage-contract.md`. Collect only the selected sprint's Reporting issue membership and fetch every referenced epic's full context separately, even outside the sprint. Process bounded epic packets in parallel **only if Quick supports actual subagents**; strict merge/independent review/global ranking remain orchestrator-owned. Then run the full `skills/sprint-intelligence/SKILL.md` workflow, with real
   independent classification review and full `sharpwriter` Quality Gate.
2. Validate the approved concise report with the allowlisted schema. Never
   export raw Jira tickets, comments, changelogs, private analyses, review
   receipts or a permanent JSON copy into Git.
3. Quick writes `data/sprints/<ID>.parquet`. The provided Quick-side publisher
   (`skills/sprint-intelligence/scripts/pages/export.py`) writes and verifies
   this file if Quick's Python environment exposes DuckDB.
4. **Quick rebuilds `data/history.parquet` from the canonical sprint Parquet
   files on every change**. Do not allow stale indexes to be published.
5. Review the diff for the new/updated Parquet and history index. Commit and
   push. GitHub Actions does no Parquet conversion and installs no runtimes.
6. The browser runs pinned DuckDB-Wasm and loads only selected Parquet data.

Example Quick-side export command (never in CI):

```sh
python skills/sprint-intelligence/scripts/pages/export.py \
  --input "$RUN/approved-sprint.json" \
  --publication-gate "$RUN/out/publication_gate.json" \
  --quality "$RUN/out/quality.json" \
  --selection "$RUN/out/highlight_selection.json" \
  --report "$RUN/report.md" \
  --manifest "$RUN/report-manifest.json" \
  --receipt "$RUN/sharpwriter-receipt.json" \
  --repo /path/to/sprint-int
```

Produce the compact payload before `quality_gate.py publish --payload`; the exporter rechecks exact quality, report, selection, receipt and payload digests. Details: [docs/QUALITY-INTEGRITY.md](docs/QUALITY-INTEGRITY.md).

`report_json` is a compact nested column *inside the canonical Parquet file*,
not a separate file. Scalar metrics are native columns. Confirm the publication
security model: GitHub Pages assets can be downloaded by viewers.

## Repository procedures

Read [docs/UPDATE-PROCESS.md](docs/UPDATE-PROCESS.md) for the exact update,
correction, deployment and recovery sequence; [docs/DATA-CONTRACT.md](docs/DATA-CONTRACT.md)
for the enforced fields and current Parquet v2 layout; and
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for trust boundaries and the
browser loading sequence.

Schema additions require the ordered procedure in [docs/SCHEMA-EVOLUTION.md](docs/SCHEMA-EVOLUTION.md) **before** the next export. `schema_version=2` is required on new approved sprint payloads; old v1 files remain unmodified.

Quick must publish `data/sprints/<ID>.parquet`, `data/history.parquet`, and `data/manifest.json` in one reviewed Git commit. The manifest is a SHA-256 consistency seal generated by the exporter, not a proof of Jira or sharpwriter authenticity. Failed or interrupted multi-file updates must be recovered with `--index-only` after confirming the canonical sprint set. CI rejects stale hashes and unlisted static files.

Jira comment extraction (mandatory): [COMMENT-EXTRACTION.md](docs/COMMENT-EXTRACTION.md). Full pagination and per-issue comment coverage are required for FINAL.

For the exact executable stage sequence, stop conditions and recovery rules, read [`docs/EXECUTION-HARNESS.md`](docs/EXECUTION-HARNESS.md).
