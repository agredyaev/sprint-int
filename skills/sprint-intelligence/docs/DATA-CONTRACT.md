# Data contract

## Source-universe boundaries

| Dataset | Membership rule | Lifetime | Included in sprint delivery counts? |
|---|---|---|---|
| `issues.jsonl` | Issues returned by exhaustive query for the selected sprint, routed to Reporting by verified ownership | Temporary Quick workspace | Eligible roots only, after evidence checks |
| `epic_context.jsonl` | One record per named parent epic of sprint issues, even when epic itself is outside the sprint | Temporary Quick workspace | No: context only |
| Dependency source records | Linked DWH/external prerequisites for Reporting work | Temporary Quick workspace | No |
| `work_packets.jsonl` / `packet_results.jsonl` | Deterministically assigned current-sprint issue keys | Temporary Quick workspace | Classification inputs, not aggregates |
| `report.md` / reviews / gate receipts | Checked outcome evidence, ranked highlights, publication verification | Temporary Quick workspace | No direct publication |
| Approved JSON handoff | Allowlisted short report after all gates pass | Temporary; outside Git | Becomes canonical Parquet |
| `data/sprints/<id>.parquet` | One approved Reporting sprint | Git and GitHub Pages | Canonical published snapshot |
| `data/history.parquet` | Rebuilt from **all** canonical sprint files | Git and GitHub Pages | Derived summary only |
| `data/manifest.json` | SHA-256/size seal of the complete Parquet file set, generated by Quick | Git and GitHub Pages | Consistency metadata only; not a report source |

The input sprint membership is not the set of all tasks under its parent epics.
A completed sibling from an earlier sprint cannot be counted as a current
sprint completion. Original sprint commitment cannot be inferred from current
membership without a baseline or changelog.

## Temporary extraction contract

Required by `sprint_pipeline.py prepare`:

```text
snapshot.json
  selected sprint ID, window, as_of, extraction page coverage,
  Exact provider_issue_keys and verified per-key exclusion evidence
issues.jsonl
  one normalized record for each admitted sprint member issue;
  parent/subtask/epic links and dated evidence
epic_context.jsonl
  one context record for each referenced named epic;
  goal, description, acceptance criteria, ownership, source pointers,
  context_status = complete | partial | unavailable
```

Missing epic rows stop packet preparation. A `partial` or `unavailable`
context prevents selecting that substantive epic as a final highlight; a
fabricated context is never an acceptable fallback.

`prepare` emits `out/work_packets.jsonl`, `out/issue_features.jsonl` and
`out/coverage.json`. Each packet carries its epic context and no more than
12 issues / 12,000 JSON characters by default. Each issue key must belong to
exactly one packet. `merge-packets` rejects missing/duplicate packet results,
wrong epic assignments and missing/extra/duplicate issue keys.

For field-level source rules see:
[extraction.md](../references/extraction.md),
[schema.md](../references/schema.md) and
[orchestration.md](../references/orchestration.md).

## Approved report handoff

`validate_report.py` accepts only the following top-level fields (v2 exports require `sprint.schema_version = 2`):

```text
sprint         sprint identity, window, published_at, concise narrative,
               reviewed_issues, optional team/is_demo
metrics        eight required numeric metrics; v2 permits one nullable optional metric
epics         approved Reporting product/strategic initiatives
dependencies  verified cross-team dependencies linked to a Reporting epic
quality        classification, scope, evidence, sharpwriter, publication
```

The serialized field names are exactly `sprint`, `metrics`, `epics`,
`dependencies`, `quality` (without whitespace). Extra keys are rejected.
Each `quality` value must equal `"passed"`, but these are **attestations only**;
the exporter does not run or authenticate the five gates. The orchestrator must
verify their actual PASS outputs before creating the handoff.

Required fields in `sprint`: `id`, `started_on`, `ended_on`, `period_label`,
`executive_summary`, `pulse`, `attention`, `reviewed_issues`, `published_at`.
Optional fields: `team`, `attention_owner`, `is_demo`. For current v2 exports, `schema_version = 2` is required; older v1 payloads omit it. `id` matches
`[0-9A-Za-z._-]{1,48}`. Dates use ISO 8601; `started_on <= ended_on`.

`epics[]` includes `jira_key`, `title`, `domain`, `category`, `status`,
`objective`, `delivered`, `planned_next`, `jira_url`, `tasks` and optional
allowlisted summary fields; categories are `product` or `strategic`.
`reporting_scope` must be `in_scope` and `delivery_team` must be `Reporting`
when present. Tasks must be Reporting-owned and have Jira links.
`dependencies[]` may refer to DWH/external work but must attach to a listed
Reporting epic. The allowed status vocabulary is:

```text
DELIVERED  PROGRESSING  BLOCKED  AT_RISK  NO_PROGRESS  UNKNOWN
```

All Jira issue references must use valid issue keys and HTTPS browse/Jira URLs.
Title and narrative length limits are enforced by `validate_report.py`.
The published `epics[].tasks[]` array is a curated subset of short reviewed
Reporting task summaries, **not** a raw export of every sprint ticket.

Detailed source/approval hashing and fail-closed handoff are specified in [QUALITY-INTEGRITY.md](QUALITY-INTEGRITY.md).

## Metric fields and cross-checks

| Metric | Physical type | Validator constraint |
|---|---|---|
| `material_outcomes` | BIGINT | Count of all independently confirmed material outcomes, not only selected highlights (minimum is the number of ranked highlights) |
| `blocked_initiatives` | BIGINT | Count of Reporting epics with `status=BLOCKED` |
| `at_risk_initiatives` | BIGINT | Count of Reporting epics with `status=AT_RISK` |
| `verified_time_saved_hours` | DOUBLE | Nonnegative finite measured hours, or `NULL` when no defensible measurement exists; `0` means verified zero |
| `manual_operations` | BIGINT | Nonnegative; computed upstream |
| `automation_candidates` | BIGINT | Nonnegative; computed upstream |
| `automation_delivered` | BIGINT | Nonnegative; computed upstream |
| `active_initiatives` | BIGINT | Exactly `len(epics)` |

The JSON validator requires native integers for BIGINT count metrics (no floats or booleans) and finite numbers for DOUBLE metrics. It rejects out-of-range values; it
does **not** independently recompute hours saved, manual-operation counts or
AI/automation evidence. Independent evidence review remains mandatory.

## Canonical Parquet v1 and v2

`skills/sprint-intelligence/scripts/pages/parquet_store.py` implements
versioned one-row sprint files. The current Quick writer emits **v2 only**.
It can still read and validate existing v1 files without rewriting them.

The v1 physical columns remain frozen:

```text
sprint_id VARCHAR, ended_on VARCHAR, period_label VARCHAR,
published_at VARCHAR, is_demo BOOLEAN,
material_outcomes BIGINT, blocked_initiatives BIGINT,
at_risk_initiatives BIGINT, verified_time_saved_hours DOUBLE,
manual_operations BIGINT, automation_candidates BIGINT,
automation_delivered BIGINT, active_initiatives BIGINT,
report_json VARCHAR
```

The v2 physical columns add `schema_version BIGINT` after `sprint_id`
and nullable `customer_impact_score DOUBLE` before `report_json`; other
column types and meanings are unchanged. The v2 approved handoff includes
`sprint.schema_version = 2`. This optional score is an example extension;
leave it absent/`NULL` without a documented measurement. Allowed measured
values are finite numbers from 0 through 100. Older v1 handoffs have no
version key. v1 is **read-only**; new Quick exports cannot create it.

The Parquet index `data/history.parquet` is always regenerated in the **v2
scalar layout**, excluding `report_json`, from every canonical sprint.
It has exactly one row per sprint, ordered by `ended_on DESC, sprint_id DESC`.
For v1 reports, the index writes `schema_version = 1` and
`customer_impact_score = NULL`. It must not substitute zero for an unknown
measurement. Read-back compares all derived index rows, not just IDs.

- Path: `data/sprints/<sprint.id>.parquet`.
- Compression: ZSTD; one row; validated read-back before staged commit.
- `data/manifest.json` must enumerate every canonical file with its ID, schema version, SHA-256 digest and exact byte length. A mismatched manifest blocks CI.
- Manifest writes are last; ordinary exceptions roll back the whole update. Process termination can still interrupt the multi-file commit; CI rejects incomplete sets.
- Reader limit: 2,000,000 bytes per sprint file.
- `report_json` remains a compact **approved** nested report, not raw source.
- An existing sprint ID needs a fully re-reviewed correction plus `--replace`.
- Existing v1 snapshots must not be rewritten solely to align schemas.
- Physical version detection uses exact column names/order plus the embedded
  `sprint.schema_version` in v2. Unknown formats or version mismatches fail.

**Mandatory schema-change procedure:**
[SCHEMA-EVOLUTION.md](SCHEMA-EVOLUTION.md). This covers version increments,
nullable additive columns, history rebuilding, DuckDB-Wasm changes, tests,
publication and recovery. Adding a column in Parquet alone is not sufficient.

## Confidentiality and publication boundary

Never commit or publish Jira descriptions, comments, changelogs, full epic
source descriptions, Confluence page bodies, packet results, classification
reviews, sharpwriter receipts, secrets or transient transfer JSON. Publishing
approved summaries still requires approval for the actual GitHub Pages audience.
Any visitor permitted to retrieve a Parquet asset can download the entire file,
regardless of client-side filters or hidden UI elements.
